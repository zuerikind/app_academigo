**Locked decisions:**
- Slot is reserved (not deducted) on booking request — create_booking RPC holds credits as reserved
- Teacher clicks "Mark complete" to trigger complete_booking RPC (credit deduction + earning record)
- cancel_booking RPC returns reserved credits atomically
- meeting_link is required to confirm — return error if missing
- topic_note is optional; update booking row after RPC call (2-step is acceptable per RESEARCH.md)
- Booking decline: calls cancel_booking RPC (same as cancel — returns reserved credits)
- Both student AND teacher can cancel (cancelBooking action must validate caller is student OR teacher on that booking)

**Existing RPC signatures (from migration 20260528000005_booking_rpcs.sql):**
- create_booking(p_student_id, p_teacher_id, p_subject_id, p_start_time, p_end_time, p_credits_to_reserve)
  → returns booking UUID; after Phase 3-01 migration also accepts p_topic_note DEFAULT NULL
- complete_booking(p_booking_id) → sets status='completed', moves credits from reserved to used, inserts teacher_earnings row
- cancel_booking(p_booking_id) → sets status='cancelled', returns reserved credits to student

**Supabase infers join types as arrays** — cast profiles join with `as unknown as { full_name: string | null }` pattern established in Phase 2. Check existing queries in lib/queries/admin.ts for the pattern.

Create lib/actions/bookings.ts with `"use server"`:

`requestBooking(_prev, formData)`:
- requireRole("student")
- Extract teacherId, startTime, topicNote (max 500 chars) from formData
- Derive endTime = startTime + 50 minutes
- Call supabase.rpc("create_booking", { p_student_id, p_teacher_id, p_start_time, p_end_time, p_credits_to_reserve: 1, p_topic_note: topicNote || null })
- Map error: "insufficient_credits" in message → return { error: "Not enough credits. Please purchase a package." }
- revalidatePath; return { bookingId }

`confirmBooking(_prev, formData)`:
- requireRole("teacher")
- Extract bookingId, meetingLink from formData
- Return { error: "Meeting link is required." } if meetingLink is empty
- Update bookings set status='confirmed', meeting_link=meetingLink where id=bookingId AND teacher_id=teacher.id
- revalidatePath; return {}

`declineBooking(_prev, formData)`:
- requireRole("teacher")
- Extract bookingId from formData
- Verify booking belongs to this teacher (teacher_id = teacher.id)
- supabase.rpc("cancel_booking", { p_booking_id: bookingId })
- revalidatePath; return {}

`markComplete(_prev, formData)`:
- requireRole("teacher")
- Extract bookingId from formData
- Verify booking teacher_id = teacher.id and status = 'confirmed'
- supabase.rpc("complete_booking", { p_booking_id: bookingId })
- revalidatePath; return {}

`cancelBooking(_prev, formData)`:

- Simpler: use createClient and supabase.auth.getUser() to get current user; look up booking; verify caller is either student.profile_id or teacher.profile_id on that booking
- supabase.rpc("cancel_booking", { p_booking_id: bookingId })
- revalidatePath; return {}

`getTeacherBookings(profileId)`:
```typescript

  id, status, start_time, end_time, topic_note, meeting_link, created_at,
  students (
    id,

BEGIN:VEVENT\r\n

DTSTART:{formatIcsDate(startTime)}\r\n
DTEND:{formatIcsDate(endTime)}\r\n
SUMMARY:Academigo lesson with {teacherName}\r\n
DESCRIPTION:{meetingLink}\r\n
END:VEVENT\r\n
END:VCALENDAR
```
